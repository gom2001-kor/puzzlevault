# AdSense 심사 준비와 광고 활성화 운영 가이드

확인일: 2026-09-28(KST). 범위: PuzzleVault 저장소, 공개 URL의 응답, Google 공식 문서. AdSense 계정 안의 승인 상태, 실제 광고 재고와 매출은 확인하지 않았습니다. 이전 사용자가 제공한 화면의 문제는 **가치가 별로 없는 콘텐츠**였습니다. 소유권 확인 완료와 사이트 광고 게재 승인은 서로 다른 단계입니다.

## 이번에 확인·수정한 기술 사항

- 실광고 SDK와 보상형/전면 광고는 계속 기본 비활성입니다. 기존 `ads.txt`와 `google-adsense-account` 메타 태그의 게시자 ID는 `pub-6035096210993315`로 일치합니다.
- 광고 provider를 나중에 연결해도 **매 요청에 `canRequestAds(kind)`를 확인**합니다. 함수가 없거나 미허용, 예외, 잘못된 반환값이면 광고를 요청하지 않고 힌트는 무료로 제공합니다. 시청 동의 직후의 허용 상태도 재확인합니다. 이 함수 자체는 CMP가 아닙니다.
- `refreshBottomAd()`는 계속 아무 작업도 하지 않습니다. 60초 간격이면 광고 자동 갱신이 허용된다는 오래된 프로젝트 지침을 삭제했습니다.
- 루트 언어 미들웨어는 정확한 `pv_lang` 쿠키와 브라우저 언어 우선순위를 따릅니다. `q=0` 언어를 선택하지 않으며, 리다이렉트 때 쿼리를 보존합니다. `Vary: Accept-Language, Cookie`와 `private, no-store`로 다른 방문자에게 이전 언어가 캐시되는 것을 막습니다. `/ads.txt`, `/robots.txt`, 명시한 콘텐츠 URL은 이 리다이렉트에서 제외됩니다.
- `/sw.js` 재검증, `ads.txt`·`robots.txt` 텍스트 응답/재검증, 404 페이지 noindex 헤더를 명시했습니다. `robots.txt`는 공개 콘텐츠와 광고 크롤러를 차단하지 않습니다.

공개 서버 읽기 점검에서는 `/ads.txt`가 HTTP 200, `text/plain`으로 위 ID를 반환했습니다. 반면 존재하지 않는 `/ad-audit-missing-page-20260928`도 HTTP 200 HTML을 반환해 잘못된 주소가 홈으로 표시되는 문제를 확인했습니다. 루트 `404.html`을 포함하는 새 정적 배포로 해결하고 실제 운영 URL의 HTTP 404를 확인해야 합니다. 로컬 테스트만으로 운영 응답 수정까지 완료됐다고 판단하지 않습니다.

## 심사 전에 할 일

1. 개선한 공개 산출물을 `puzzlevault.pages.dev`에 배포합니다. 저장소 소스 전체 대신 정리된 공개 디렉터리/ZIP을 사용합니다. 변경된 학습 자료, 원문 출처와 자체 설명, 게임 가이드가 로그아웃 상태에서 정상적으로 열리는지 확인합니다.
2. 홈, 한국어 홈, 게임, 블로그, 영어 학습 안내, 소개·문의·개인정보, `ads.txt`, `robots.txt`, 없는 URL을 확인합니다. 학습 앱이 작동한다는 사실뿐 아니라 방문자가 어떤 내용을 배우고 어떻게 이용하는지 읽을 수 있어야 합니다.
3. AdSense → **사이트**에서 실제 신청 주소와 표시된 사유를 확인합니다. 현재 소유권 확인을 유지합니다. 새로 연결해야 하는 경우 사이트에 이미 존재하는 **메타 태그 또는 ads.txt** 방식을 선택할 수 있습니다. 소유권 확인만 하려고 자동 광고 SDK를 다시 추가할 필요는 없습니다. [Google 사이트 연결 방법](https://support.google.com/adsense/answer/12169212?hl=en)
4. 실제 문의 수신 여부와 수정 요청 처리 경로를 운영자가 확인합니다. 제공되지 않은 운영자 이름, 이메일, 경력, 수상·사용자 수를 만들어 넣지 않습니다.
5. 오류와 콘텐츠 문제를 고친 공개 버전을 확인한 뒤 해당 사이트에서 **검토 요청**을 진행합니다. 이 작업에서는 계정에 로그인하거나 검토 요청을 제출하지 않았습니다. 승인 여부는 Google이 판단합니다. [사이트가 준비되지 않았을 때의 조치](https://support.google.com/adsense/answer/12176698?hl=en)

글 개수·단어 수·방문자 수를 늘렸다는 이유만으로 승인이 보장되지 않습니다. 자동 생성된 문장을 늘리는 것보다 실제 게임 규칙·예시·풀이 비교, 학습 자료의 출처와 문맥 설명, 동작하는 도구와 탐색 경험을 제공하는 데 초점을 둡니다. 비어 있는 화면, 오류·설정 화면, 단순 탐색 화면을 광고 지면으로 삼지 않습니다. [게시자 콘텐츠가 없는 화면 정책](https://support.google.com/publisherpolicies/answer/11112688?hl=en)

## 승인 후 일반 디스플레이 광고

현재 저장소에는 승인된 실광고 단위나 CMP가 연결되어 있지 않습니다. 아래 단계는 계정 확인이 필요한 운영 절차입니다.

1. 사이트가 **Ready/준비됨**인지와 실제 게시자 ID를 확인하고 AdSense에서 실제 광고 단위를 만듭니다. 슬롯 ID를 임의로 만들지 않습니다.
2. 최초 배치는 충분한 설명이 있는 블로그·가이드의 본문 뒤로 제한하는 것을 이 사이트의 시작 구성으로 권장합니다. 이는 Google이 지정한 의무 배치가 아니라 조작 오클릭을 줄이기 위한 프로젝트 판단입니다. 게임·학습 퀴즈의 입력 버튼 주변이나 결과 팝업에 일반 디스플레이 광고를 삽입하지 않습니다.
3. 자동 광고를 사용할 때 게임/학습 상호작용 URL의 제외 설정과 앵커·전면 형식을 계정에서 먼저 점검합니다. 설정·백업·오류 화면처럼 광고에 적합하지 않은 경로/영역도 제외합니다. 빈 기존 `.ad-slot`을 일괄 활성화하지 않습니다.
4. Google은 게임 경계에서 콘텐츠 광고를 **최소 150px 떨어뜨리거나 게임 페이지에서 제거할 것**을 강하게 권장합니다. 이는 모든 광고 형식의 승인을 보장하는 단일 수치가 아닙니다. 320px 모바일부터 데스크톱까지 버튼, 드래그 영역, 이동 메뉴와 실제 광고의 관계를 확인합니다. [게임 페이지 광고 안내](https://support.google.com/adsense/answer/2768340?hl=en)
5. 광고와 본문을 명확히 구분합니다. 일반 디스플레이 광고 클릭에 힌트·점수·현금 등의 보상을 약속하지 않습니다. 자동 갱신, 자체 클릭, 친구에게 광고 클릭 요청, 유료 클릭 유입을 하지 않습니다. [Google 광고 배치 정책](https://support.google.com/adsense/answer/1346295?hl=en)

## 개인정보와 동의

현재 하단의 개인정보 선택은 **선택형 Analytics**를 제어합니다. 광고에 대한 Google 인증 CMP도, 광고 동의를 받았다는 증거도 아닙니다. 게임·영어 학습 기록을 유지하기 위한 필수 로컬 저장과 광고 추적을 구분합니다.

Google 최신 공식 문서는 EEA·영국·스위스의 **개인맞춤 광고**에 Google 인증 및 IAB TCF 통합 CMP를 요구합니다. 비개인맞춤·제한 광고에는 별도 조건과 지원 범위가 있으며, 비개인맞춤이라는 이름만으로 개인정보 의무가 없어지는 것은 아닙니다. 광고 제품·지역·모드에 맞는 고지와 선택을 실제로 구현해야 합니다. 이 프로젝트는 광고 활성화 전에 AdSense **개인정보 보호 및 메시지**의 Google CMP 또는 지원되는 인증 CMP를 설정·검증하는 구성을 권장합니다. [Google CMP 요구사항](https://support.google.com/adsense/answer/13554116?hl=en), [제한 광고의 조건](https://support.google.com/adsense/answer/14210870?hl=en)

운영자가 설정해야 할 사항: 서비스/운영자 식별, 정확한 개인정보 페이지, 동의·거절·선택 관리·철회 동작, 실제 사용 광고 공급자, 해당 지역의 광고 방식. CMP에서 얻는 실제 신호를 SDK 로더와 `canRequestAds(kind)`에 연결하고, 아직 준비되지 않은 상태에서는 요청하지 않습니다. 테스트할 때 허용/거절/철회/응답 실패를 각각 확인합니다.

## 게임 보상형·전면 광고는 별도 통합

일반 AdSense 배너를 자체 전체 화면에 넣고 시청 시간을 재거나, 닫기를 막아 힌트를 주는 방식으로 바꾸면 안 됩니다. 사용할 게임 광고 제품의 계정 자격과 공식 구현을 먼저 확인해야 합니다. Google을 쓴다면 H5 Games Ads / Ad Placement API 제공 여부와 실제 계정 구성을 확인합니다. [Ad Placement API](https://developers.google.com/ad-placement), [공식 콜백 계약](https://developers.google.com/ad-placement/apis)

실제 provider 계약은 [광고 연결 준비 문서](monetization-readiness.md)에 있습니다. 시청 전 보상을 구체적으로 알리고 사용자가 거절해도 기본 플레이가 가능해야 합니다. `adViewed` 등 공급자가 확인한 완료만 보상의 근거로 삼고, 닫기·광고 없음·타임아웃·오류는 중복 지급하지 않습니다. 재생 전 일시정지·음소거, 종료 후 복원은 실 SDK와 게임 양쪽에서 검증합니다. [보상 광고 정책](https://support.google.com/adsense/answer/9121589?hl=en)
